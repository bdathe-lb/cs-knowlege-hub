make

简介

Section titled “简介”

Makefile 本质上是一个构建规则文件，用于指导 make 工具自动化完成编译、打包、安装等任务。通过 Makefile，开发者可以避免手动输入繁琐的命令，只需执行 make 命令，系统就会根据 Makefile 中的规则自动完成构建过程。

Makefile 是软件开发中用于自动化构建过程的重要工具，尤其在 C/C++ 等编译型语言的项目中应用广泛。在大型项目开发中，源文件众多且依赖关系复杂，手动编译不仅效率低下，还容易出错。Makefile 能够清晰地描述文件之间的依赖关系和构建规则，实现增量编译（只重新编译修改过的文件及其依赖文 件），大大提高开发效率。

本文档旨在为自己提供一个系统、全面的 Makefile 学习查阅资料，整理学习过程中的重点知识。使用时，可根据需要查阅相应章节，快速获取所需信息。

语法结构

Section titled “语法结构”

Makefile 主要由一系列规则组成，每条规则通常包含目标（target）、依赖（prerequisites）和命令 （recipe）三部分，基本结构如下：

  • 目标（target）：目标是规则的核心，表明要构建的对象，可以是文件目标，也可以是伪目标
  • 依赖（prerequisites）：依赖是生成目标所依赖的文件或目标，当依赖文件的修改时间比目标文件晚时 ，make 会执行命令重新生成目标
  • 命令（recipe）：命令是构建目标的具体操作,命令可以是任意的 shell 命令，也可以是其他可执行程序的命令

这是一个文件的依赖关系，也就是说，target 这一个或多个的目标文件依赖于 prerequisites 中的文件，其生成规则定义在 command 中，下面区分一下文件目标和伪目标

工作流程

Section titled “工作流程”

make 的工作原理核心是 依赖管理 + 时间戳比较 + 执行命令，详细工作流程如下：

1. 读取并解析 Makefile

make 会在当前目录下按顺序寻找文件名为 GNUmakefile 、 makefile 和 Makefile 的文件，解析 Makefile 中的内容，包括变量定义、规则、条件判断、函数调用等，make 遇到 include 指令，会把其他位置的 Makefile 包含进来，被包含的文件内容会像写在主 Makefile 一样被解析

2. 确定构建目标

make 会把 Makefile 中的第一个规则中的目标作为默认目标，也可以通过命令行指定目标：make <target>，目标文件可以：

  • 文件目标（如 main、foo.o）
  • 伪目标（如clean、install）

3. 构建依赖关系链

make 从目标出发，递归解析所有的依赖项，如果依赖本身是目标，递归生成其依赖关系链，最终构建完整的依赖关系，确保依赖先于目标生成

4. 检查文件状态

对每个目标，make 通过文件修改时间（mtime）判断是否需要重新构建，规则是：

  • 目标不存在：必须执行命令生成目标
  • 目标存在：对比目标与所有依赖的修改时间
    • 如果所有依赖的修改时间都早于目标：目标是最新的，无需操作
    • 如果任一依赖的修改时间晚于目标（或依赖本身需要更新）：必须执行命令更新目标

伪目标不受文件时间影响，make 构建伪目标时总会运行其命令

5. 执行命令构建目标

当确定需要更新目标时，make 会按照依赖关系链中的顺序执行规则中的命令，保证依赖先生成。执行完成后，目标文件的修改时间会被更新，确保下次检查时能正确判断状态

模式通配符

Section titled “模式通配符”

% 是 Makefile 中最特殊的通配符，主要用于模式规则和静态模式规则中目标和依赖的模式中，% 在目标和依赖中必须成对出现，表示 “任意长度的字符串”

(1) 模式和茎

  • 模式（pattern）是带有一个 % 的字符串，可以有前缀、后缀，也可以只是 % 本身，举例：

    • %.c （前缀为空，后缀为 .c）

    • lib%.a （前缀 lib，后缀 .a）

    • % （没有前后缀）

  • 茎（stem）是% 匹配到的那部分字符串，举例：

    • 模式 %.c 匹配 test.c → 茎是 test

    • 模式 lib%.a 匹配 libhello.a → 茎是 hello

(3) 茎的传递

  • 如果目标和依赖目标都带 %，目标模式的 % 匹配目标文件名得到了茎，而每一个目标的依赖文件是使用此目标的茎代替依赖模式中的模式字符 % 而得到，这就是茎的传递，举例：

    • 目标：foo.o

    • 匹配规则 %.o → % 匹配 foo → 茎 = foo

    • 依赖：%.c → 替换 % → foo.c

    • 执行命令：$(CC) -c foo.c -o foo.o

    • 同理，bar.o 会生成 bar.o，依赖 bar.c

  • 当模式匹配包含有斜杠（包含目录名）的文件时，那么在进行模式匹配时，目录部分会首先被移开，然后进行匹配，成功后，再把目录加回去，举例：

    • 目标模式 e%t | 依赖模式 c%r | 文件 src/eat
    • 首先剥离文件的目录名，得到 eat 和模式 e%t 进行匹配，得到了 %=a，之后再把目录加回去，于是 %=src/a，得到了茎

Section titled “静态模式规则”

静态模式规则是 显式指定目标列表 的模式规则，它为一组已知的目标绑定统一的模式匹配逻辑。与模式规则的 “自动匹配” 不同，静态模式规则的目标是明确列出的，仅对这些目标生效

  • 目标模式：用 % 表示目标名称中与依赖对应的部分（如 %.o）
  • 依赖模式：用 % 关联到目标模式中的 %（如 %.c，表示 main.o 依赖 main.c）

静态模式规则和模式规则不同之处是模式规则是从全局目标中匹配符合的目标，而静态模式规则是从目标列表中匹配符合的目标

自动生成依赖关系

Section titled “自动生成依赖关系”

C/C++ 源文件之间通常通过头文件（.h）相互依赖，当某个头文件修改时，需要重新编译依赖它的源文件，手动维护依赖关系很容易出错，尤其是大型项目。自动生成依赖可以让 make 自动追踪头文件变化，如果头文件发生变化可以及时更新目标

自动生成依赖的实现方式：

最常用的方法是利用编译器的 -M 系列选项（以 GCC 为例）生成依赖规则，再通过 Makefile 的 include 指令引入这些规则

(1) GCC 生成依赖选项

GCC 提供了一系列用于生成依赖关系的选项，核心功能及区别如下：

  • -M：分析源码并输出完整依赖关系，包含用户自定义头文件和系统头文件（如 stdio.h）
  • -MM：分析源码并生成仅包含用户自定义头文件的依赖关系（忽略系统头文件，推荐使用）
  • -MF 文件名： 将分析得到的依赖规则输出到指定文件（通常使用 .d 作为后缀的依赖文件）
  • -MP：为每个依赖的头文件生成伪目标，避免头文件被删除时出现构建错误
  • -MT 目标：自定义依赖规则中的目标名称（默认目标为与源文件同名的 .o 文件）
  • -MD：编译源码时自动生成 .d 依赖文件，包含完整依赖（含系统头文件），同时生成 .o 目标文件
  • -MMD：编译源码时自动生成 .d 依赖文件，仅包含用户自定义头文件（忽略系统头文件，推荐使用），同时生成 .o 目标文件

-M / -MM

  • 直接传入源码（如gcc -MM main.c）进行依赖分析，此时分析结果直接输出到标准输出

  • 编译源码（如gcc -MM -MF main.d -c main.c -o main.o）过程中进行依赖分析，此时需要指定输出文件，否则不输出信息

-MD/-MMD

  • 直接传入源码（如gcc -MMD main.c）进行依赖分析，此时分析结果输出到文件 a-main.d
  • 编译源码（如gcc -MMD -c main.c -o main.o）过程中进行依赖分析，此时分析结果输出到文件 main.d

并行执行任务（多进程构建），n 为最大并行任务数，如果不带 n，那么 make 会自动根据 CPU 核心数决定并行数

3. -k / --keep-going

4. -n / --just-print / --dry-run

模拟执行，只打印将要执行的命令，不实际执行。用于调试 Makefile，检查命令是否正确。

示例：

5. -t / --touch

不执行命令，仅更新目标文件的时间戳（让目标看起来是最新的）。用于避免重复构建未修改的文件。

6. -B / --always-make

强制重新构建所有目标，无论文件是否有更新。

  • 1：有目标需要更新
  • 2：出错
