# 页面规范

五种页面类型。组件与令牌见 [`design-system.md`](./design-system.md)。

原型：https://claude.ai/code/artifact/0e9ee5a4-a6df-405e-b418-b21bb7458bd0

---

## 0. 数据模型

所有页面从同一份派生数据取值，**由构建时解析 `knowledge-hub/` 得到，不手工维护**。

```
Category { name, tools[] }
Tool     { name, desc, path|null, cat }
Doc      { h1, intro, heads[], lines }   // path -> Doc
```

来源：

| 字段 | 来自 |
|---|---|
| `Category` / `Tool.name` / `Tool.desc` / `Tool.path` | 解析 `linux-tools/README.md` 的索引表 |
| `Doc.h1` | 笔记的 `# ` 一级标题 |
| `Doc.heads` | 笔记的所有 `## ` 二级标题 |
| `Doc.intro` | 第一个 `## ` 之后的首个非空段落 |
| `Doc.lines` | 文件行数 |

`Tool.path` 为 `null` 即「待写」。这是全站唯一的状态判据。

> 当前真实规模：7 个分区、58 个条目、38 篇已写、20 篇待写、合计 8,310 行。

## 1. 总目录（首页）

**路由** `/`　**布局** 侧栏 + 内容（无 TOC）

自上而下四块：

### 1.1 页头
眉标 `INDEX` → `h1` 总目录 → meta 行：`N 个分区 · N 个条目 · N 篇已写 · N 行`

### 1.2 统计条
五格：`追踪条目` / `已写笔记`（accent）/ `待写`（warn）/ `覆盖度 %` / `总行数`

### 1.3 分区覆盖度
每分区一行：名称 + 进度条 + `已写/总数`，整行可点，进入分区页。

**这一块是首页存在的理由。** 平铺的条目表看不出「哪个分区欠账最多」——
`文件与目录操作` 只写了 1/13，`网络工具` 1/4，这个信息必须一眼可见。

### 1.4 分区条目网格
按分区分组，每组标题带 `已写/总数`。已写条目可点进文档页；待写条目灰化 + 右上角 `待写` 标签，不可点。

### 待写条目的处理

**保留在目录里，灰化标注，不隐藏。**

理由：现有 `linux-tools/README.md` 本来就用 `-` 标记待写，目录同时充当待办清单。
隐藏会丢掉「还有 20 个坑」这个信息，而它正是决定下一篇写什么的依据。

代价是目录变长。若确实觉得吵，备选方案是**默认折叠、点「显示待写」展开** ——
但不要直接删掉，那会让覆盖度统计失去出处。

## 2. 分区页

**路由** `/c/{分区}`　**布局** 侧栏 + 内容（无 TOC）

页头：眉标 `SECTION` → `h1` 分区名 → meta：`N 个条目 · N 篇已写 · 覆盖 N%`

主体是一张四列三线表：

| 列 | 内容 | 对齐 |
|---|---|---|
| 命令 | 行内 code | 左 |
| 说明 | 索引表里的一句话 | 左 |
| 状态 | `已写` / `待写` 标签 | 左 |
| 行数 | `Doc.lines`，待写为 `—` | **右**，`tabular-nums` |

已写行整行可点。待写行 `--kb-muted`，不可点、不悬停。

> 行数列不是凑数的。`make.md` 1624 行 vs `blkid.md` 几十行 ——
> 一眼能分出哪篇要啃、哪篇是速查。

## 3. 文档页

**路由** `/n/{path}`　**布局** 侧栏 + 内容 + TOC（三栏）

### 页头
眉标 = 所属分区 → `h1` = `Doc.h1` → meta：`{真实文件路径} · {N} 行 · {N} 个小节`

meta 里放真实路径是刻意的 —— 你会需要立刻在编辑器里打开它。

### 正文
Markdown 渲染，映射到 `design-system.md` §4 的层级表。
`##` 渲染为 accent 全大写小节标题，`###` 为 sans 14px 600。

### TOC
由 `Doc.heads` 生成，`sticky`，滚动时高亮当前小节。小节少于 2 个时不渲染 TOC，内容区占满。

### 上下篇
底部 pager，序列为**已写笔记的扁平顺序**（跨分区连续），跳过待写条目。

## 4. 搜索结果

**路由** `/search?q=`　**布局** 侧栏 + 内容（无 TOC）

查阅型站点里仅次于文档页的高频页面，不能当二等公民做。

### 检索范围与排序

按以下优先级出结果，同一 `(条目, 位置)` 去重：

| 优先级 | 匹配对象 |
|---|---|
| 0 | 条目名**前缀**匹配 |
| 1 | 条目名包含 |
| 2 | 说明包含 |
| 3 | 小节标题包含 |
| 4 | 简介正文包含 |

同级内的次级排序：**匹配位置**（越靠前越优），再次级：条目名长度。

> 这两条都是被真实数据逼出来的。搜「压缩」时 `gzip` / `xz` / `zip` / `bzip2`
> 的名字里都不含中文，全部走说明匹配，和 `tr`（字符转换/删除/压缩）同级；
> 只有比匹配位置才能把说明开头就是「压缩」的那批排到前面 —— `gzip` 命中在位置 0，
> `tr` 在位置 8。只分优先级而不比位置，`tr` 会一直霸占首位。

结果分两组呈现：**条目匹配**（上表，构建时嵌入，开发服务器下也可用）与
**正文匹配**（Pagefind 全文 + 小节锚点）。Pagefind 索引在 `build` 时生成，
`astro dev` 下不存在 —— 此时正文组显示明确提示，不静默失败。

### 结果条目

三行：

```
linux-tools/02-text-processing/awk.md        ← 真实路径，mono 10.5px muted
awk  awk › 常用选项                           ← 条目名 accent 600 + 定位 muted
awk 是一种用于文本和数据处理的编程语言…        ← 摘要，命中处 <mark> 高亮
```

`awk › 常用选项` 这种**小节级定位**是重点 —— 直接告诉你答案在哪一节，
而不是只给一个文件名让你自己翻。

### 边界

- 空查询 → 提示语，不渲染空列表
- 无结果 → 给可用的示例查询（`字段` / `压缩` / `进程`），不要只说「无结果」
- 命中待写条目 → 展示但不可点，路径位置显示 `{分区} / 待写`
- 结果上限 24 条

## 5. 速查表

**路由** `/cheatsheet`　**布局** 侧栏 + 内容（无 TOC）

对应 `cs-basics/cheatsheet/linux-cheatsheet.md`。

**这类内容需要和文档页不同的版式**：它是「扫一眼就走」，不是顺序阅读。

- 双栏 `columns: 2`，栏间 `column-gap: 34px` + `column-rule: 1px solid var(--kb-line)`
- 每个 `section` 加 `break-inside: avoid`，禁止跨栏断开
- 小节标题用 accent 全大写样式，但**不进 TOC**
- 表格更紧：12.5px，行距压到 `5px 10px 5px 0`
- 900px 以下降为单栏
- 需可直接打印 —— 不要引入依赖屏幕状态的元素

## 6. 跨页面规则

### 侧栏
所有页面共用，始终显示全部 7 个分区和 58 个条目。当前条目高亮。侧栏是唯一的全局导航，不做顶部菜单。

### 面包屑
`knowledge-hub / {分区} / {条目}`。首页只显示站名。末节不可点。

### 状态优先级
待写状态在任何页面的表现必须一致：灰化 + `待写` 标签 + 不可点 + 无悬停反馈。

### 页面标题
`{页面名} · knowledge-hub`
