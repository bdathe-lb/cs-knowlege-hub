sed

简介

Section titled “简介”

sed 是一个流编辑器，用于对文本进行转换和处理。它逐行读取输入，在内部缓冲区（模式空间）中进行操作，然后将结果输出。主要功能包括文本替换、删除、插入和筛选等，擅长批量文本处理

Section titled “基本语法”

工作原理

Section titled “工作原理”
  1. 读取输入：sed 从标准输入读取一行数据
  2. 存储在模式空间：读取的行存储在 sed 的内部缓冲区，称为模式空间
  3. 执行命令：sed 对模式空间中的内容执行用户指定的命令
  4. 输出：命令执行完毕后，sed 将模式空间的内容输出到标准输出，然后清空模式空间，准备处理下一行

重复上述操作，直到文件末尾

常用选项

Section titled “常用选项”

选项列表

选项 说明
-e 添加执行的 command，可以多次使用多个 -e 来执行多个命令，通常省略也可以
-n 取消默认输出，只有明确用 p 命令时才会打印输出
-i 直接把修改结果写回原文件（危险操作，谨慎使用）
-f script.sed 从指定文件中读取 sed 脚本
--version 查看 sed 版本信息
--help 查看帮助信息

命令列表

命令 功能
s 替换指定字符
p 打印行
d 删除行
a 插入文本到指定行后
i 插入文本到指定行前
c 替换整行内容
q 提前退出
r 读入文件内容并插入原文本
w 将匹配的内容写入文件
{} 多条命令组合
= 显示行号

  • i：忽略大小写
  • <N>：替换第 <N> 个匹配项

c：整行替换

Section titled “c：整行替换”

语法：

命令 说明
<N>c 新内容 将第 N 行替换为“新内容”
<N,M>c 新内容 将第 N 到 M 行合并成一行，替换为“新内容”
/pattern/c 新内容 将匹配正则的行替换为“新内容”

如果插入的内容是多行，用 \ 分割

示例：

sed '3c 第一行content\n第二行content' file.txt 这样写是错的，因为 \n 不会被识别为换行，sed 会把整段当作一行插入

p：打印

Section titled “p：打印”

通常要搭配 -n 选项使用，否则可能重复打印

语法：

命令 说明
'<N>p' 打印第 N 行
'<N,M>p' 打印第 N-M 行
'/pattern/p' 打印匹配正则的行
'/pattern/!p' 打印不匹配正则的行

命令 说明
'<N>d' 删除第 N 行
'<N,M>d' 删除第 N ~ M 行
'/pattern/d' 删除匹配正则的行

语法：

命令 说明
<N>a 内容 在第 N 行后插入一行文本
/pattern/a 内容 在匹配的行后插入文本

i：前插

Section titled “i：前插”

语法：

命令 说明
<N>i 内容 在第 N 行前插入一行文本
<N,M>i 内容 在第 N ~ M 行每行前插入内容
/pattern/i 内容 在匹配的行前插入文本

如果插入的内容是多行，用 \ 分割

sed '2i 第一行content\n第二行content' file.txt 这样写是错的，因为 \n 不会被识别为换行，sed 会把整段当作一行插入

语法：

语法格式 说明
<N>r 文件名 在第 N 行后插入文件内容

w：写入

Section titled “w：写入”

该命令用于将匹配的行内容写入指定的文件中，同时也会将原行输出到标准输出（除非使用 -n 取消默认输出）。

语法：

语法 说明
<N>w 文件名 将第 N 行写入指定文件
<N,M>w 文件名 指定行范围写入文件
/pattern/w 文件名 将匹配正则的行写入文件

{}：命令块

Section titled “{}：命令块”

{} 用于把多条 sed 命令组合在一起，针对同一个地址或模式范围一起执行。大括号内命令之间用分号 ; 或换行分隔。

语法：

  • 地址：可以是行号、地址范围（N,M）、模式匹配（/pattern/）等
  • command1..N：大括号里的一条或多条 sed 命令

示例：

=：行号

Section titled “=：行号”
命令 说明
sed '=' file.txt 显示每一行的行号
sed -n '10{=;p}' 显示第 10 行的行号和内容
sed -n '/main/{=;p}' 显示包含 “main” 的行号和内容
sed '=' file.txt | paste - - 将行号和内容合并在一行显示（推荐）

注意事项

Section titled “注意事项”

进行原地替换时，例如 sed s/REGEX/SUBSTITUTION/ input.txt > input.txt 并不是安全的做法。当使用 > 重定向输出时，shell 会先打开目标文件并将其截断（清空内容），然后才执行 sed 命令。这意味着 sed 试图读取的是已经被清空的文件，最终导致原文件内容丢失。

这不是 sed 特有的行为，而是 shell 重定向机制导致的。任何使用 command input > input 形式的命令（如 awk、grep 等）都会遇到同样的问题，因为文件截断发生在命令执行之前。
