# 页面规范

五种页面类型。组件与令牌见 [`design-system.md`](./design-system.md)。

原型：https://claude.ai/code/artifact/0e9ee5a4-a6df-405e-b418-b21bb7458bd0

---

## 0. 数据模型

所有页面从同一份派生数据取值，**由构建时解析 `knowledge-hub/` 得到，不手工维护**。

```
Category { name, tools[] }
Tool     { name, desc, path|null, cat }
Doc      { h1, intro, heads[], lines }   // path -> Doc
Cheat    { title, source, groups[], refs[] }   // url -> Cheat，见 §5
```

来源：

| 字段 | 来自 |
|---|---|
| `Category` / `Tool.name` / `Tool.desc` / `Tool.path` | 解析 `linux-tools/README.md` 的索引表 |
| `Doc.h1` | 笔记的 `# ` 一级标题 |
| `Doc.heads` | 笔记的所有 `## ` 二级标题 |
| `Doc.intro` | 第一个 `## ` 之后的首个非空段落 |
| `Doc.lines` | 文件行数 |

`Tool.path` 为 `null` 即「待写」。这是全站唯一的状态判据。

> 当前规模（分区、条目、已写 / 待写、总行数）跑 `make sync` 查看，不在文档里写死。

## 1. 总目录（首页）

**路由** `/`　**布局** 侧栏 + 内容（无 TOC）

`h1` 之后直接是分区条目网格，没有中间层。

按分区分组，每组标题是 `分区名`（可点，进分区页）+ 右侧 `已写/总数`。
已写条目可点进文档页；待写条目灰化 + 右上角 `待写` 标签，不可点。

### 曾经有过统计条和覆盖度块，已移除

原设计在 `h1` 和条目网格之间插了两块：五格统计条（追踪条目 / 已写 / 待写 /
覆盖度 % / 总行数）和七行分区覆盖度进度条。

移除的理由：**同一份数字在页面上出现了三次** —— 统计条、覆盖度行、以及每个分区
标题右侧的 `已写/总数`，侧栏分组标签里还有第四份。它们合起来把真正要查的条目网格
推出了首屏，与「密度优先」直接冲突（设计规范 §2 原则一）。

分区级的 `已写/总数` 保留在分区标题和侧栏里，信息没有丢失，只是不再重复陈列。

> 教训：结构装置要编码真实信息（设计规范 §2 原则三），但「真实」不等于
> 「值得单独占一块版面」。已经在别处表达过的信息，再列一遍就退化成装饰了。

### 待写条目的处理

**保留在目录里，灰化标注，不隐藏。**

理由：现有 `linux-tools/README.md` 本来就用 `-` 标记待写，目录同时充当待办清单。
隐藏会丢掉「还有 20 个坑」这个信息，而它正是决定下一篇写什么的依据。

代价是目录变长。若确实觉得吵，备选方案是**默认折叠、点「显示待写」展开** ——
但不要直接删掉，那会让覆盖度统计失去出处。

## 2. 分区页

**路由** `/c/{分区}`　**布局** 侧栏 + 内容（无 TOC）

页头：眉标 `SECTION` → `h1` 分区名

主体是一张四列三线表：

| 列 | 内容 | 对齐 |
|---|---|---|
| 命令 | 行内 code | 左 |
| 说明 | 索引表里的一句话 | 左 |
| 状态 | `已写` / `待写` 标签 | 左 |
| 行数 | `Doc.lines`，待写为 `—` | **右**，`tabular-nums` |

已写行整行可点。待写行 `--kb-muted`，不可点、不悬停。

> 行数列不是凑数的。`make.md` 1624 行 vs `blkid.md` 几十行 ——
> 一眼能分出哪篇要啃、哪篇是速查。

## 3. 文档页

**路由** `/n/{path}`　**布局** 侧栏 + 内容 + TOC（三栏）

### 页头
眉标 = 所属分区 → `h1` = `Doc.h1`

### 正文
Markdown 渲染，映射到 `design-system.md` §4 的层级表。
`##` 渲染为 accent 全大写小节标题，`###` 为 sans 14px 600。

### TOC
由 `Doc.heads` 生成，`sticky`，滚动时高亮当前小节。小节少于 2 个时不渲染 TOC，内容区占满。

### 上下篇
底部 pager，序列为**已写笔记的扁平顺序**（跨分区连续），跳过待写条目。

## 4. 搜索结果

**路由** `/search?q=`　**布局** 侧栏 + 内容（无 TOC）

查阅型站点里仅次于文档页的高频页面，不能当二等公民做。

### 检索范围与排序

按以下优先级出结果，同一 `(条目, 位置)` 去重：

| 优先级 | 匹配对象 |
|---|---|
| 0 | 条目名**前缀**匹配 |
| 1 | 条目名包含 |
| 2 | 说明包含 |
| 3 | 小节标题包含 |
| 4 | 简介正文包含 |

同级内的次级排序：**匹配位置**（越靠前越优），再次级：条目名长度。

> 这两条都是被真实数据逼出来的。搜「压缩」时 `gzip` / `xz` / `zip` / `bzip2`
> 的名字里都不含中文，全部走说明匹配，和 `tr`（字符转换/删除/压缩）同级；
> 只有比匹配位置才能把说明开头就是「压缩」的那批排到前面 —— `gzip` 命中在位置 0，
> `tr` 在位置 8。只分优先级而不比位置，`tr` 会一直霸占首位。

结果分两组呈现：**条目匹配**（上表，构建时嵌入，开发服务器下也可用）与
**正文匹配**（Pagefind 全文 + 小节锚点）。Pagefind 索引在 `build` 时生成，
`astro dev` 下不存在 —— 此时正文组显示明确提示，不静默失败。

### 结果条目

三行：

```
linux-tools/02-text-processing/awk.md        ← 真实路径，mono 10.5px muted
awk  awk › 常用选项                           ← 条目名 accent 600 + 定位 muted
awk 是一种用于文本和数据处理的编程语言…        ← 摘要，命中处 <mark> 高亮
```

`awk › 常用选项` 这种**小节级定位**是重点 —— 直接告诉你答案在哪一节，
而不是只给一个文件名让你自己翻。

### 边界

- 空查询 → 提示语，不渲染空列表
- 无结果 → 给可用的示例查询（`字段` / `压缩` / `进程`），不要只说「无结果」
- 命中待写条目 → 展示但不可点，路径位置显示 `{分区} / 待写`
- 结果上限 24 条

## 5. 速查表

**路由** `/cheatsheet`　**布局** 侧栏 + 内容（无 TOC）　**源** `cs-basics/cheatsheet/linux-cheatsheet.md`

版式是**一张密表**：左列命令、右列效果、分组用一条粗线隔开。

打开这一页只有一个动作 —— 找到某个命令然后走。所以扫读密度是唯一指标，
眼睛只需要沿一条竖线往下走，不用在块之间跳。

| 元素 | 处理 |
|---|---|
| 分组行 | 小节名，mono 全大写 accent，上方 `--kb-bd-th` 粗线起头 |
| 说明行 | 散文退居注释位：11.5px `--kb-muted`，无下边框 |
| 条目行 | `<th scope="row">` 命令（`nowrap`）+ `<td>` 效果，行间 `--kb-bd-hair` |
| 参考资料 | 页脚一行，不单独成组 |
| 悬停 | 整行 `--kb-accent-bg`；分组行与说明行不响应 |
| 560px 以下 | 命令列允许换行，否则长命令挤没说明 |
| 打印 | 去掉悬停底色 |

### 结构在同步时转换，不在页面

原文是**代码块 / 表格 / 段落三种分立的块**，密表要把它们合并成统一的行。
这层合并 CSS 做不到，因此 `sync.mjs` 在同步时就解析成结构化数据，
页面只负责渲染 —— **速查页不渲染 Markdown**。

```
Cheat { title, source, groups[], refs[] }
Group { name, note, rows[] }
Row   { cmd, desc }
Ref   { text, href }
```

四条确定性规则（`scripts/sync.mjs` §3b）：

| 源中的块 | 转换为 |
|---|---|
| 围栏内完全没有 `#` | 该分组的说明（流程图一类） |
| `#` 独占一行，下一行是命令 | 注释作说明，命令作条目 |
| `#` 出现在命令右侧 | 以第一个 `#` 切开，左命令右说明 |
| Markdown 表格 | 首列作命令，次列作说明 |
| 只含链接的小节 | 页脚参考资料，不单独成组 |

不匹配任何规则的代码块会在同步时打**警告**，绝不静默丢弃。
分组数、条数和警告数在 `make sync` 的输出里。

> 副作用：页面不再经过 Markdown 管线，因此压制 expressive-code
> 外壳（终端圆点栏、复制按钮、横向滚动条）的那一整套覆盖规则可以全部删除。

### 曾经是双栏流式版式，已废弃

原设计用 `columns: 2` 让 Markdown 内容自然流动。实际渲染下**块与栏互相打架** ——
代码块和表格是不可分割的块，栏高却由流动决定，结果是小节被断到下一栏、
左右长短不齐、三个终端拟物的圆点栏和三条横向滚动条堆在窄栏里。

先尝试过减法修复（剥掉外壳、代码换行），能缓解但治不了根：
**问题出在「让文档流决定版式」这个前提**，不在样式细节。

## 7. 跨页面规则

### 页头不放统计眉条
分区页、搜索页、速查表曾各有一行 `N 个条目 · N 篇已写 · 覆盖 N%` 这样的元信息。
已全部删除 —— 和 §1 删掉总目录统计条是同一个理由：这些数字在紧接着的表格里
一数就有，放在页头只是把正文往下推一行（设计规范 §2 原则一、原则二）。
`.kb-meta` 的 CSS 已一并移除，不留死样式。

### 侧栏
所有页面共用，始终显示全部分区和条目。当前条目高亮。侧栏是唯一的全局导航，不做顶部菜单。

全局入口按**使用频次**排：总目录 / 速查表 / 搜索。

### 界面文案不以句号收尾
空态、提示、状态这类文案是**标签**，不是散文 —— 末尾不加「。」。
句中该断的地方照常用标点：`输入关键词开始搜索。试试 字段、压缩、进程、awk`
（中间那个句号在分句，末尾那个只是噪声）。

### 面包屑
`knowledge-hub / {分区} / {条目}`。首页只显示站名。末节不可点。

### 状态优先级
待写状态在任何页面的表现必须一致：灰化 + `待写` 标签 + 不可点 + 无悬停反馈。

### 页面标题
`{页面名} · knowledge-hub`
